# Itération 3 — mon propre correctif était incomplet

*2026-09-09 · cas 1 de la boucle (défaut d'instrument) · aucun budget consommé*

## Ce que l'itération 1 avait manqué

I8 repliait les doublons de rang par **empreinte exacte** du `xrank`. Le premier
balayage d'après-correctif montre que ça ne suffit pas : `pos_crowd_vs_univ` et
`lsr_globacct_x` **sortent encore comme deux lignes distinctes**, avec des
chiffres identiques à la deuxième décimale.

```
lsr_globacct_x     mkt h3 k12 hd1 sm0 DIR   net 23.39   t 3.59
pos_crowd_vs_univ  mkt h3 k12 hd1 sm0 DIR   net 23.39   t 3.59
```

Mesuré :

```
même motif de NaN          : False
cellules communes          : 126 950
cellules qui diffèrent     : 0
jours où la couverture diffère : 19 / 943
```

Les deux signaux sont **identiques partout où ils sont tous les deux définis**.
Ils ne diffèrent que par la couverture de 19 jours. L'empreinte exacte les
sépare — le NaN entre dans le hash — mais le PnL ne les sépare pas.

Une empreinte exacte est donc le mauvais critère : elle est trop stricte, et
elle sous-compte les doublons, ce qui est précisément l'erreur que I8 devait
corriger.

## Le correctif

`_rank_dedup` a maintenant **deux étages** :

1. **empreinte exacte** du rang — replie les doublons parfaits, en O(n)
2. **accord sur les cellules communes** — comparaison par paires sur un
   échantillon fixe de 40 000 cellules, repli si ≥ 99,9 % d'accord là où les
   deux sont définis, avec un recouvrement minimum de 500 cellules

Représentant : le premier par ordre alphabétique. Déterministe. Coût mesuré :
**11,2 s** sur la grille complète.

| | avant I8 | après I8 | après I10 |
|---|---|---|---|
| noms | 183 | 183 | 183 |
| **essais réels** | 183 | 142 | **138** |
| noms repliés | 0 | 41 | 45 |

```
lsr_globacct_x == ['pos_crowd_vs_univ', 'pos_crowd_x']
lsr_ttacct_x   == ['pos_ttacct_vs_univ', 'pos_ttacct_x']
```

## Pourquoi ça compte plus que 4 noms

C'est exactement le couple qui a causé la **violation** enregistrée à
l'itération 1 : `sweep_v5` a relu la fenêtre scellée sur `pos_crowd_vs_univ`,
déjà jugé sous le nom `lsr_globacct_x`. Le correctif de l'itération 1 n'aurait
**pas** empêché la récidive. Celui-ci l'empêche.

La leçon générale : un correctif d'instrument doit être vérifié sur la sortie
qu'il est censé changer, pas seulement sur un test isolé. C'est le balayage
complet — relancé après coup — qui a montré que les deux lignes étaient encore là.
